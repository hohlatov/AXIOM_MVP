# AXIOM

Персональный ИИ-репетитор 24/7 для подготовки к ОГЭ. См. `docs/` — ТЗ, контракт
интеграции с ИИ-сервисом и **полный стратегический аудит** (код vs документация
vs живой MVP vs рынок) — начать стоит с `docs/AXIOM-STRATEGIC-AUDIT-V2.md` и
`docs/AXIOM-DECISION-MEMO.md`.

## Аудит и что из него уже сделано

Аудит (сентябрь 2026) нашёл, что заявленная в питч-деке «ИИ-часть» (RAG,
CAT/IRT-диагностика, DKT) на момент проверки полностью замокана, плюс две
CRITICAL security-находки. Часть находок уже закрыта веткой
`implementation/audit-fixes-and-skill-map` (не смёржена в `main` — ждёт ревью):

- **Security (CRITICAL/HIGH)**: `.env` был закоммичен в git без `.gitignore`
  (плейсхолдер `JWT_SECRET`, но сам факт трекинга — проблема) — исправлено,
  `.env` untracked, `.gitignore` добавлен. **Если на проде `.env` до сих пор
  содержит дефолтный `JWT_SECRET` — его нужно вручную заменить и передеплоить,
  иначе можно подделать JWT для любого аккаунта.** Порты Postgres/Redis в
  `docker-compose.yml` были открыты на весь интернет — сужены до `127.0.0.1`.
  VK OAuth `state` теперь реально проверяется на callback (защита от login
  CSRF). Rate limiting теперь учитывает `X-Forwarded-For` за реверс-прокси
  (было: считал адрес прокси, а не клиента) + добавлен лимит на
  `assistant/chat` до включения платного ИИ. Подробности — `docs/security/security-audit.md`.
- **`POST /auth/refresh`** — сессия больше не обрывается через 60 минут
  без возможности переавторизации; фронтенд сам обновляет access-токен по 401.
- **Живая карта навыков (Skill Mastery Map)** — выбранная по аудиту killer
  feature (`docs/product/04-killer-feature.md`): детерминированная EWMA-оценка
  владения темой (`knowledge_state`), обновляется после каждой попытки в
  тренажёре, видна на дашборде. Подбор следующего задания в тренажёре теперь
  берёт эту же оценку вместо отдельно считаемой accuracy.
- **Честная маркировка** — диагностика и ИИ-ассистент показывают заметку
  «упрощённая версия», пока за ними не стоит настоящий ИИ-сервис — не вводит
  пользователей (в т.ч. несовершеннолетних) в заблуждение.

Что из находок аудита **ещё не сделано** — см. `docs/architecture/technical-debt.md`
и `docs/roadmap/90-day-plan.md` (в частности: мажорный апгрейд Next.js из-за
CVE, событийная аналитика, канал обратной связи, `ON DELETE CASCADE` на FK от
`users`).

## Статус

**Backend — все 5 компонентов MVP готовы и прогнаны end-to-end** (Postgres + Redis,
не только unit-уровень):

- [x] Auth — регистрация/логин/`me`/`refresh`, VK ID (полный флоу, включая
      страницу `/auth/vk/callback` на фронте и серверную проверку `state`
      против login CSRF), восстановление пароля, **согласие родителя/законного
      представителя при регистрации** (152-ФЗ, обязательное поле, для VK ID —
      отдельный экран подтверждения перед созданием нового аккаунта)
- [x] Личный кабинет / дашборд — прогресс и рекомендации из результатов
      диагностики (пока mock, см. ниже) + **живая карта навыков** по реальным
      данным тренажёра
- [x] Тренажёр — подбор темы по живой карте навыков (`knowledge_state`,
      EWMA — приоритет непройденным и самым слабым темам), мгновенная
      проверка с разбором ошибки. **Банк заданий — 45** (37 математика по 7
      темам + 8 русский язык). Сид-скрипт идемпотентен — безопасно
      перезапускать, не плодит дубли. Содержание — типовые школьные задачи в
      стиле ОГЭ с проверенными ответами, не официальный банк ФИПИ; стоит, чтобы
      кто-то с педагогическим бэкграундом (например, Валерия) пробежался по
      формулировкам перед показом реальным ученикам
- [x] Диагностика (обвязка) — сессии/ответы/результаты хранятся у нас, генерация
      вопросов делегирована ИИ-сервису Валентины (сейчас в mock-режиме,
      `AI_SERVICE_MOCK=true` — результат не зависит от ответов ученика, на
      фронте теперь есть честная заметка об этом)
- [x] ИИ-ассистент (обвязка) — `POST /assistant/chat` (авто-создание сессии,
      история диалога хранится у нас), `GET /assistant/sessions/{id}/history`.
      Тот же паттерн, что у диагностики: backend хранит переписку, генерацию
      ответа делегирует сервису Валентины, сейчас работает в mock-режиме (на
      фронте — та же честная заметка); лимит 30 запросов/час на пользователя
      уже стоит на будущее подключение платного ИИ
- [x] Rate limiting на auth-эндпоинтах и на `assistant/chat` — на Redis, без
      новых зависимостей. Тройная защита: по IP (с учётом `X-Forwarded-For` за
      реверс-прокси), по email отдельно (защита конкретного аккаунта от
      перебора) и по `user_id` для `assistant/chat`. Лимиты: регистрация
      5/час/IP, логин 8/15мин/IP + 5/15мин/email, запрос сброса пароля
      5/час/IP + 3/час/email, подтверждение сброса 15/час/IP, VK callback
      20/час/IP, refresh 30/15мин/IP, assistant/chat 30/час/пользователя. При
      превышении — 429 с заголовком `Retry-After`. Учёт `X-Forwarded-For`
      корректен настолько, насколько прокси перед приложением гарантированно
      перезаписывает (а не добавляет к) этот заголовок от клиента — стоит
      подтвердить это отдельно для конкретной прод-инфраструктуры (RelaxDev).

**Frontend (Next.js 14 + TypeScript + Tailwind) — первая версия готова:**

- [x] Страницы: логин (+ссылка «Забыли пароль?»), регистрация (+VK ID,
      +чекбокс согласия родителя), дашборд (+карта навыков), тренажёр,
      диагностика (+заметка «упрощённая версия»), восстановление пароля
      (`/forgot-password` — запрос, `/reset-password?token=...` —
      подтверждение), **ИИ-ассистент** (`/assistant` — чат-интерфейс, история
      сообщений, +заметка «упрощённая версия»), `/auth/vk/callback` — приём
      редиректа от VK с экраном согласия для новых аккаунтов
- [x] Общий каркас с навигацией, авторизация через JWT в localStorage
      (access + refresh, автообновление по 401), редирект неавторизованных
      на `/login`, logout доступен на всех размерах экрана (раньше был скрыт
      на мобильных)
- [x] Design-система: тёплый нейтральный фон, индиго/тил/охра палитра,
      едва заметная сетка «в клетку» как фирменный элемент (отсылка к тетради
      по математике)
- [x] Собирается без ошибок (`npm run build`, тайпчек чистый), линт настроен
      и чист (`npm run lint` — раньше `.eslintrc` не было вообще)
- [ ] **Нет публичного лендинга и страницы цен** — `/` сразу редиректит на
      `/login` или `/dashboard`, показать продукт до регистрации нечем (см.
      `docs/product/02-ux-ui-audit.md`)
- [ ] **Не протестировано целиком в реальном браузере в рамках последней сессии
      работы** — сквозной API-флоу (регистрация → тренажёр → карта навыков)
      прогнан вживую против реального поднятого backend, но не кликом в
      браузере. Более ранний ручной прогон в браузере подтверждён владельцем
      (Александр)
- [ ] Next.js 14.2.35 содержит непропатченные CVE (включая unauthenticated
      RCE-advisory) — фикс требует мажорного апгрейда до 16.x (breaking
      changes), сознательно отложен, но начиная с публичного деплоя на
      `axiom-mvp.relaxdev.ru` это уже не «риск для внутреннего демо», см.
      `docs/security/security-audit.md`

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Backend: http://localhost:8000/docs · Frontend: http://localhost:3000

Миграции и тестовые данные (после того как контейнер `db` поднят):

```bash
docker compose exec backend alembic upgrade head
docker compose exec backend python -m app.seed_tasks   # примеры заданий тренажёра
```

Если БД уже поднималась раньше (миграции применялись до появления таблицы
`knowledge_state`, добавленной для живой карты навыков) — `alembic upgrade head`
достаточно, миграция аддитивна и ничего не ломает в существующих данных.

**Важно про фронтенд:** `NEXT_PUBLIC_API_URL` вшивается в JS-бандл на этапе
`npm run build`, а не читается в рантайме. Если backend будет на другом домене —
поменяйте `NEXT_PUBLIC_API_URL` в `.env` **и пересоберите** фронтенд
(`docker compose build frontend`), одного перезапуска контейнера недостаточно.

## Автотесты

Backend покрыт pytest-набором (**49 тестов**) — формализует все ручные сценарии
проверки: регистрацию, VK OAuth (включая CSRF-защиту через `state`), сброс
пароля, refresh-токен, тренажёр (включая подбор темы по живой карте навыков и
саму EWMA-математику), полный цикл диагностики, чат ассистента (включая
rate limit по пользователю), дашборд, rate limiting на auth, плюс граничные
случаи (401/404/409/422/429, изоляция чужих сессий/данных, идемпотентность).

```bash
cd axiom-backend
pip install -r requirements-dev.txt --break-system-packages
createdb axiom_test   # отдельная БД, dev-данные не трогает
pytest -v
```

Тесты используют mock-режим ИИ-сервиса (`AI_SERVICE_MOCK=true` выставляется
автоматически в `tests/conftest.py`), отдельный индекс Redis (`/1` вместо
`/0`) и `NullPool` для соединений с БД — без него пул asyncpg периодически
ловит `another operation is in progress` при пересечении короткоживущих
сессий с соединениями фикстур. Таблицы полностью пересоздаются в начале
сессии тестов и очищаются между тестами (кроме `trainer_tasks` — это контент,
сидится один раз; тест, добавляющий свою тестовую задачу в эту таблицу,
обязан сам удалить её в конце — см. `test_next_task_prioritizes_weaker_topic_by_knowledge_state`
в `tests/test_trainer.py` как пример).

Фронтенд: `npm run build` (тайпчек внутри сборки), `npm run lint`
(ESLint, `next/core-web-vitals`) — оба должны быть чистыми. E2E-тестов
(Playwright/Cypress) пока нет, см. `docs/qa/test-strategy.md`.

## Структура репозитория

```
axiom-backend/      — FastAPI backend
axiom-frontend/      — Next.js frontend
docs/                — ТЗ, аудит, архитектура, безопасность, бизнес, роадмап
  audit/              — карта репозитория, раннтайм-аудит, live vs code, red team
  product/            — продуктовый/UX-аудит, killer feature, граф знаний ОГЭ
  architecture/        — текущая/целевая архитектура, БД, API, ИИ-репетитор, техдолг
  security/            — полный security-аудит
  qa/                  — стратегия тестирования
  business/            — бизнес-модель, рынок, конкуренты, финмодель, GTM
  roadmap/             — продуктовый роадмап, 90-дневный план
  AXIOM-STRATEGIC-AUDIT-V2.md, AXIOM-DECISION-MEMO.md — сводные документы аудита
docker-compose.yml   — оркестрация: db, redis, backend, frontend
```

ИИ-сервис (RAG-ассистент, диагностика CAT/IRT) — отдельный репозиторий/контейнер
Валентины, подключается по HTTP согласно `docs/ai-service-contract.md`.
Переменные `AI_SERVICE_URL` и `AI_SERVICE_MOCK` — в `.env`.
