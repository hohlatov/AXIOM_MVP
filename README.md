# AXIOM

Персональный ИИ-репетитор 24/7 для подготовки к ОГЭ. См. `docs/` — ТЗ и контракт
интеграции с ИИ-сервисом.

## Статус

**Backend — все 5 компонентов MVP готовы и прогнаны end-to-end** (Postgres + Redis,
не только unit-уровень):

- [x] Auth — регистрация/логин/`me`, VK ID (полный флоу, включая страницу
      `/auth/vk/callback` на фронте — раньше её не было и VK-вход не мог
      завершиться, см. «Найденные и исправленные баги» ниже), восстановление
      пароля, **согласие родителя/законного представителя при регистрации**
      (152-ФЗ, обязательное поле, для VK ID — отдельный экран подтверждения
      перед созданием нового аккаунта)
- [x] Личный кабинет / дашборд — прогресс и рекомендации берутся из реальных
      результатов диагностики
- [x] Тренажёр — адаптивный подбор темы, мгновенная проверка с разбором ошибки.
      **Банк заданий расширен до 45** (37 математика по всем 7 темам из отчёта
      тестирования Валентины + 8 русский язык — раньше `subject=russian` вообще
      не работал, возвращал 404). Сид-скрипт идемпотентен — безопасно
      перезапускать, не плодит дубли. Содержание — типовые школьные задачи в
      стиле ОГЭ с проверенными ответами, не официальный банк ФИПИ; стоит, чтобы
      кто-то с педагогическим бэкграундом (например, Валерия) пробежался по
      формулировкам перед показом реальным ученикам
- [x] Диагностика (обвязка) — сессии/ответы/результаты хранятся у нас, генерация
      вопросов делегирована ИИ-сервису Валентины (сейчас в mock-режиме,
      `AI_SERVICE_MOCK=true`)
- [x] ИИ-ассистент (обвязка) — `POST /assistant/chat` (авто-создание сессии,
      история диалога хранится у нас), `GET /assistant/sessions/{id}/history`.
      Тот же паттерн, что у диагностики: backend хранит переписку, генерацию
      ответа делегирует сервису Валентины, сейчас работает в mock-режиме
- [x] Rate limiting на auth-эндпоинтах — на Redis, без новых зависимостей.
      Двойная защита: по IP (защита от распределённого спама) и по email
      отдельно (защита конкретного аккаунта от перебора, даже если атакующий
      меняет IP). Лимиты: регистрация 5/час/IP, логин 8/15мин/IP + 5/15мин/email,
      запрос сброса пароля 5/час/IP + 3/час/email, подтверждение сброса
      15/час/IP, VK callback 20/час/IP. При превышении — 429 с заголовком
      `Retry-After`. **За реверс-прокси на проде `request.client.host` будет
      адресом прокси, а не клиента** — см. TODO в `app/core/rate_limit.py`,
      нужно донастроить перед деплоем (доверенный `X-Forwarded-For` или лимит
      на уровне самого балансировщика)

**Frontend (Next.js 14 + TypeScript + Tailwind) — первая версия готова:**

- [x] Страницы: логин (+ссылка «Забыли пароль?»), регистрация (+VK ID,
      +чекбокс согласия родителя), дашборд, тренажёр, диагностика,
      восстановление пароля (`/forgot-password` — запрос,
      `/reset-password?token=...` — подтверждение), **ИИ-ассистент**
      (`/assistant` — чат-интерфейс, история сообщений),
      `/auth/vk/callback` — приём редиректа от VK с экраном согласия
      для новых аккаунтов
- [x] Общий каркас с навигацией, авторизация через JWT в localStorage,
      редирект неавторизованных на `/login`
- [x] Design-система: тёплый нейтральный фон, индиго/тил/охра палитра,
      едва заметная сетка «в клетку» как фирменный элемент (отсылка к тетради
      по математике)
- [x] Собирается без ошибок (`npm run build`, тайпчек чистый), протестировано:
      backend поднят, страницы отдаются, CORS настроен и проверен preflight-запросом,
      статические JS-чанки грузятся
- [ ] **Не протестировано в реальном браузере** — в этой рабочей среде нет сети
      до Chromium/CDN для headless-браузера. Полный сценарий (регистрация →
      диагностика → тренажёр → дашборд) вручную подтверждён рабочим в реальном
      браузере (Александр). Сброс пароля через UI прогнан end-to-end по API
      (запрос → ссылка из лога → подтверждение → старый пароль не работает) —
      саму страницу `/reset-password` в браузере стоит один раз кликнуть глазами,
      когда будет настроена реальная отправка почты
- [ ] Есть предупреждение старой версии Next.js (уязвимость из советника
      декабря 2025) — уже обновлено до патченной 14.2.35, но перепроверьте
      `npm audit` перед продакшном, так как security-рекомендации меняются.
      На момент последней сверки `npm audit` находит новые CVE в Next.js 14.x,
      требующие мажорного апгрейда до 16.x (breaking changes) — сознательно не
      обновляли прямо перед показом коллегам без возможности всё перепроверить.
      Проверили: проект не использует ни один из уязвимых механизмов (Server
      Actions, Middleware, i18n Pages Router, кастомный сервер) — риск для
      внутреннего демо низкий, но апгрейд нужно сделать до реального
      прод-деплоя

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Backend: http://localhost:8000/docs · Frontend: http://localhost:3000

Миграции и тестовые данные (после того как контейнер `db` поднят):

```bash
docker compose exec backend alembic upgrade head
docker compose exec backend python -m app.seed_tasks   # примеры заданий тренажёра
```

**Важно про фронтенд:** `NEXT_PUBLIC_API_URL` вшивается в JS-бандл на этапе
`npm run build`, а не читается в рантайме. Если backend будет на другом домене —
поменяйте `NEXT_PUBLIC_API_URL` в `.env` **и пересоберите** фронтенд
(`docker compose build frontend`), одного перезапуска контейнера недостаточно.

## Автотесты

Backend покрыт pytest-набором (33 теста) — формализует все ручные сценарии
проверки, что гонялись при разработке: регистрацию, сброс пароля, тренажёр,
полный цикл диагностики, чат ассистента, дашборд, rate limiting, плюс
граничные случаи (401/404/409/422/429, изоляция чужих сессий, идемпотентность).

```bash
cd axiom-backend
pip install -r requirements-dev.txt --break-system-packages
createdb axiom_test   # отдельная БД, dev-данные не трогает
pytest -v
```

Тесты используют mock-режим ИИ-сервиса (`AI_SERVICE_MOCK=true` выставляется
автоматически в `tests/conftest.py`), отдельный индекс Redis (`/1` вместо
`/0`) и `NullPool` для соединений с БД — без него пул asyncpg периодически
ловит `another operation is in progress` при пересечении короткоживущих
сессий с соединениями фикстур. Таблицы полностью пересоздаются в начале
сессии тестов и очищаются между тестами (кроме `trainer_tasks` — это контент,
сидится один раз).

## Структура репозитория

```
axiom-backend/      — FastAPI backend
axiom-frontend/      — Next.js frontend
docs/                — ТЗ, архитектура, контракт интеграции с ИИ-сервисом
docker-compose.yml   — оркестрация: db, redis, backend, frontend
```

ИИ-сервис (RAG-ассистент, диагностика CAT/IRT) — отдельный репозиторий/контейнер
Валентины, подключается по HTTP согласно `docs/ai-service-contract.md`.
Переменные `AI_SERVICE_URL` и `AI_SERVICE_MOCK` — в `.env`.
