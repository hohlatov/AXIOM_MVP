# AXIOM — контракт интеграции с ИИ-сервисом

Черновик для согласования с Валентиной. Наш backend обращается к её сервису как к
обычному HTTP API. Она может менять внутреннюю реализацию как угодно — контракт
(эндпоинты, формат запроса/ответа) должен оставаться стабильным.

Базовый URL сервиса задаётся переменной окружения `AI_SERVICE_URL`
(например, `http://axiom-ai:8100` в Docker Compose).

## 1. Чат-ассистент (RAG)

`POST /v1/assistant/chat`

Запрос:
```json
{
  "user_id": "uuid",
  "subject": "math | russian",
  "message": "текст вопроса ученика",
  "history": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

Ответ:
```json
{
  "answer": "текст объяснения «на пальцах»",
  "sources": ["опционально: ссылки на фрагменты учебника/ФИПИ"],
  "latency_ms": 1234
}
```

Требование к качеству (из ТЗ): ответ ≤ 5 сек, точность ≥ 90%.

## 2. Диагностика (CAT/IRT)

`POST /v1/diagnostics/next-item` — получить следующий вопрос адаптивного теста

Запрос:
```json
{ "session_id": "uuid", "subject": "math", "previous_answers": [
  {"item_id": "...", "answer": "текст ответа ученика"}
]}
```

> **Важно:** backend передаёт сырые ответы ученика, а не признак `correct` —
> у backend нет банка правильных ответов, только у сервиса Валентины. Оценка
> правильности и IRT-логика — полностью на стороне ИИ-сервиса.

Ответ:
```json
{ "item_id": "...", "question": "...", "options": ["..."], "is_final": false }
```

`POST /v1/diagnostics/finalize` — завершить сессию и получить карту пробелов

Запрос: тот же формат, что у `next-item` (session_id, subject, previous_answers).

Ответ:
```json
{ "topics": [ {"topic": "Уравнения", "ability_score": 0.42, "weak": true} ] }
```

Требование к качеству: тест ≤ 45 минут, покрытие кодификатора ОГЭ.

## 3. Общие правила

- Backend отвечает за: аутентификацию пользователя, хранение истории/результатов,
  бизнес-логику вокруг данных. AI-сервис — только за генерацию ответа/вопроса
  по переданному контексту, он не хранит профили пользователей.
- Ошибки — стандартный HTTP + JSON `{"error": "описание"}`, backend обязан
  обрабатывать таймаут и недоступность сервиса без падения всего приложения.
- Версионирование через префикс `/v1/` — при breaking change заводим `/v2/`.

**Статус: черновик.** Финальные поля и названия — на усмотрение Валентины,
это отправная точка для обсуждения, не жёсткая спецификация.

## 4. Открытый вопрос: скорость ответа

Тест модели (Qwen2.5-3B-Instruct, 4-bit, CPU) показал точность 88.3% и среднее
время ответа 38.4 сек — на CPU. Требование ТЗ: ≤5 сек. Пока нет замеров на GPU,
контракт выше описан как синхронный запрос-ответ, но если на GPU время
ответа всё равно будет заметно больше нескольких секунд, эндпоинт `/v1/assistant/chat`
нужно будет переделать на асинхронный паттерн (например: `POST /v1/assistant/chat/start`
возвращает `job_id`, клиент опрашивает `GET /v1/assistant/chat/{job_id}` или
получает результат через WebSocket). **Решить после первых замеров на GPU.**
