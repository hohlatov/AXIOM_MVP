# Фаза 12 — Приоритизация фич AXIOM

Статус: АУДИТ / ПРЕДЛОЖЕНИЕ. Код не менялся. Источники: `docs/audit/01-project-map.md` (карта того, что реально есть в коде), `docs/product/01-product-audit.md`, `docs/product/02-ux-ui-audit.md`, `docs/product/04-killer-feature.md`.

## Методика

Классификация: **KEEP** (оставить как есть) / **CHANGE** (оставить функцию, изменить реализацию) / **REMOVE** (убрать) / **POSTPONE** (отложить, не делать на MVP+) / **NEW** (новая фича).

Приоритет: **P0 Critical** (блокирует честный запуск на реальных пользователях) / **P1 High** (нужно для MVP+, основная гипотеза) / **P2 Useful** (полезно, не блокирует) / **P3 Later** (Launch/V1/Scale).

## 3. Особый случай: что делать с диагностикой и ИИ-ассистентом прямо сейчас (до их полной реализации)

Это не вписывается напрямую в KEEP/CHANGE/REMOVE/NEW, поэтому вынесено отдельно как решение с наивысшим приоритетом (P0):

Показывать константный результат диагностики и статичную заглушку чата **как будто это персонализация** — форма обмана пользователя (в том числе несовершеннолетнего), даже если непреднамеренная. До реализации либо карты навыков (заменяет фиктивный прогресс на честный, реагирующий на попытки в тренажёре), либо рабочего ИИ-сервиса — рекомендация:
1. Либо явно пометить эти экраны как «в разработке» / «скоро» без вывода фиктивных чисел и ответов.
2. Либо временно скрыть их из основной навигации до готовности хотя бы одного честного слоя адаптивности (карта навыков).

Это решение находится на стыке продукта и этики работы с несовершеннолетними пользователями — требует явного решения владельца продукта, не технической доработки.

## 4. Сводная приоритетная очередь (P0 → P3)

**P0 (блокирует честный запуск на реальных пользователях, делать до/одновременно с первым публичным трафиком):**
1. Убрать/честно пометить фиктивные данные диагностики и ИИ-ассистента (раздел 3).
2. Исправить баг мобильного логаута.
3. Внедрить минимальную аналитику событий (`docs/product/analytics-spec.md`).

**P1 (MVP+, основная гипотеза адаптивности и удержания):**
4. Живая карта навыков (killer feature).
5. Публичный лендинг.
6. Онбординг.
7. Канал обратной связи пользователь → команда.
8. Сузить/предупредить о несоответствии класса (8/10/11) и контента.
9. Расширить банк тренажёра по графу знаний (тестовая часть русского, геометрия как текстовые задачи).

**P2 (полезно, не блокирует основную гипотезу):**
10. Explain-my-mistake (зависит от готовности ИИ-сервиса).
11. Персональный план с дедлайном.
12. Решение по странице цен (даже если решение — «пока нет цен»).
13. Геометрия с визуальным рендером.
14. Явное решение по pgvector (использовать или убрать).

**P3 (Launch/V1/Scale):**
15. Реальная CAT/IRT-диагностика.
16. Автопроверка развёрнутого ответа.
17. Родительский кабинет.
18. Мобильное приложение / Telegram-бот.
19. RAG / Deep Knowledge Tracing / RL-планировщик.

Распределение по срокам (NOW / MVP / MVP+ / Launch / V1 / Scale) — `docs/roadmap/product-roadmap-v2.md`. Первые 90 дней исполнения — `docs/roadmap/90-day-plan.md`.
