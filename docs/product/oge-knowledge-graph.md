# Фаза 11 — Модель знаний ОГЭ (Topic → Skill → Subskill → Prerequisite → Task Type → Error Pattern → Explanation → Practice)

Статус: АУДИТ / ПРОЕКТИРОВАНИЕ. Код не менялся. Источники: код `axiom-backend/app/seed_tasks.py` (фактический банк заданий), `docs/product/01-product-audit.md`, `docs/product/04-killer-feature.md` (карта навыков выбрана как killer feature), открытый веб-поиск по ФИПИ (см. раздел 0 про достоверность).

## 0. Достоверность внешних данных — важная оговорка

Задача фазы — сверить модель знаний с актуальными требованиями ОГЭ. Прямая выгрузка официального кодификатора/спецификации ФИПИ на 2026 год (`ma_9_2026.zip`, `ru_9_2026.zip`, раздел [fipi.ru/oge/demoversii-specifikacii-kodifikatory](https://fipi.ru/oge/demoversii-specifikacii-kodifikatory)) — архив, который инструменты веб-доступа в рамках этого аудита не могут распаковать и прочитать напрямую. Вторичные источники (блоги подготовки к экзаменам) дают частично противоречивые цифры (например, «25» и «26» заданий по математике в разных источниках за 2026 год) — это типичный для таких агрегаторов шум, а не основание для точного числа.

**Что взято с высокой уверенностью (структура ОГЭ стабильна много лет, подтверждается несколькими независимыми источниками):**
- Математика ОГЭ состоит из двух частей: часть 1 — задания с кратким ответом (алгебра + геометрия + реальная математика), часть 2 — задания с развёрнутым решением (более сложная алгебра и геометрия).
- Русский язык ОГЭ состоит из трёх частей: изложение (сжатие прослушанного текста), тестовая часть (орфография/пунктуация/грамматика/анализ текста), сочинение (выбор одного из вариантов 13.1/13.2/13.3).
- Экзамен по математике в 2026 году делает более выраженный акцент на «реальную математику» (практические задачи) и геометрию — источники сходятся в этом направлении изменений, конкретные веса — нет.

**Что помечено НЕИЗВЕСТНО и требует прямой проверки перед наполнением реального банка заданий:**
- Точное число заданий части 1 / части 2 по математике на 2026 год (источники расходятся: 19+6=25 — историческая модель последних лет, либо 26 по одному из найденных источников).
- Точное число заданий тестовой части по русскому языку на 2026 год.
- Максимальный первичный балл и шкала перевода в оценку на 2026 год (может меняться год к году).
- Даты экзаменационной кампании 2026 года по конкретному региону (обычно конец мая — июнь, точные даты утверждает Рособрнадзор ежегодно).

**Рекомендация:** перед наполнением производственного банка заданий (не MVP-заглушки) кто-то из команды должен вручную скачать `ma_9_2026.zip` / `ru_9_2026.zip` с fipi.ru и свериться построчно — это 30–60 минут работы, которые нельзя заменить веб-поиском по вторичным источникам. До этого момента структура ниже — рабочая гипотеза с HIGH-уверенностью на уровне тем/навыков и MEDIUM-уверенностью на уровне точных счётчиков заданий.

Источники (просмотрено 2026-09-11): [fipi.ru — демоверсии, спецификации, кодификаторы](https://fipi.ru/oge/demoversii-specifikacii-kodifikatory), агрегаторы (100balльный блог, Экзамер, kedu.ru) — использованы только для направления изменений, не как источник точных цифр.

## 1. Текущее покрытие в коде — что реально есть сегодня

Прямая проверка `axiom-backend/app/seed_tasks.py` (45 заданий, единственный источник контента тренажёра):

| Предмет | Темы в коде сегодня | Чего нет из полного кодификатора |
|---|---|---|
| Математика | Уравнения, Проценты, Неравенства, Прогрессии, Функции, Системы (уравнений), Вероятность | **Геометрии нет вообще** (ни планиметрии, ни задач на площади/окружности) — при том, что геометрия усилена в ОГЭ-2026 по направлению изменений; нет отдельной «реальной математики» (практические задачи вне процентов); нет части 2 (развёрнутый ответ) — только задания с кратким ответом |
| Русский язык | Морфология, Орфография, Пунктуация, Фонетика | Нет изложения (сжатие текста) и сочинения (13.1/13.2/13.3) — двух из трёх частей экзамена целиком; нет синтаксиса на уровне анализа предложения/текста, нет лексики, нет работы с текстом (микротемы, средства связи) |

Вывод: сегодняшний банк — это фрагмент части 1 по обоим предметам, ориентированный на задания с однозначным кратким ответом (что закономерно — тренажёр умеет только точное сравнение строки/числа, см. `docs/product/01-product-audit.md`). Целые классы навыков ОГЭ (геометрия, развёрнутые ответы, работа с текстом) не представлены не потому, что решили отложить, а потому что автопроверка для них не реализована.

## 2. Модель знаний — математика

Формат на узел: **Тема → Навык → Поднавык → Пререквизит(ы) → Тип задания (часть/номер по кодификатору) → Типовые ошибки → Подход к объяснению → Требование к практике**.

### 2.1 Числа и вычисления
- **Навыки:** действия с рациональными числами, степени и корни, стандартный вид числа, сравнение чисел.
- **Пререквизит:** нет (базовый уровень, 5–6 класс).
- **Тип задания:** часть 1, краткий ответ.
- **Типовые ошибки:** знаковые ошибки при действиях с отрицательными числами; путаница порядка операций.
- **Объяснение:** пошаговый разбор с явным проговариванием правила знаков и порядка действий.
- **Практика:** большой объём коротких заданий, так как это фундамент для всех остальных тем — ошибка здесь маскируется под ошибку в теме верхнего уровня.

### 2.2 Проценты и доли *(в коде есть — 5 заданий)*
- **Навыки:** нахождение процента от числа, нахождение числа по проценту, процент изменения (рост/снижение), сложные проценты (вклады).
- **Поднавыки:** прямая задача vs обратная задача vs задача на разность/изменение.
- **Пререквизит:** числа и вычисления (2.1), дроби.
- **Тип задания:** часть 1, №8–9 кодификатора (номера ориентировочные, требуют сверки — см. раздел 0).
- **Типовые ошибки:** путают «на сколько % изменилось» и «во сколько раз изменилось»; берут процент от неправильной базы (от новой цены вместо старой при снижении).
- **Объяснение:** явное построение уравнения «что от чего берём», а не заучивание формулы.
- **Практика:** уже покрыто в коде (5 заданий, разумный разброс сложности 1–2).

### 2.3 Алгебраические выражения
- **Навыки:** раскрытие скобок, приведение подобных, формулы сокращённого умножения, разложение на множители.
- **Пререквизит:** числа и вычисления.
- **Тип задания:** часть 1.
- **Типовые ошибки:** ошибки знака при раскрытии скобок с минусом перед ними; неполное разложение на множители.
- **Объяснение:** визуальное выделение того, что происходит со знаком при раскрытии скобки.
- **Практика:** в коде явно не выделено отдельной темой — частично покрывается внутри «Уравнения», нужен отдельный узел графа.

### 2.4 Уравнения и неравенства *(в коде есть — 7 + N заданий)*
- **Навыки:** линейные уравнения, квадратные уравнения (дискриминант, теорема Виета), дробно-рациональные уравнения, линейные и квадратные неравенства, системы уравнений.
- **Поднавыки:** метод переноса, метод разложения на множители, метод подстановки/сложения для систем.
- **Пререквизит:** алгебраические выражения (2.3).
- **Тип задания:** часть 1 (простые) и часть 2 (более сложные системы, неравенства с параметром).
- **Типовые ошибки (из объяснений в коде видно, что учтены частично):** потеря корня при делении обеих частей на выражение с переменной; ошибка знака при переносе; для неравенств — забывают сменить знак при делении на отрицательное число.
- **Объяснение:** для квадратных — явный выбор метода (дискриминант vs Виета) с обоснованием, почему выбран этот метод.
- **Практика:** покрыто в коде (Уравнения, Неравенства, Системы — 3 отдельные темы), но всё — часть 1; часть 2 (более сложные системы/неравенства с обоснованием) отсутствует.

### 2.5 Числовые последовательности и функции *(в коде есть — Прогрессии, Функции)*
- **Навыки:** арифметическая и геометрическая прогрессия (формула n-го члена, сумма), линейная/квадратичная функция и её график, чтение графика.
- **Пререквизит:** алгебраические выражения, уравнения.
- **Тип задания:** часть 1.
- **Типовые ошибки:** путают формулу n-го члена арифметической и геометрической прогрессии; ошибка в считывании координат по графику.
- **Практика:** покрыто в коде на базовом уровне.

### 2.6 Геометрия *(в коде НЕТ — критический пробел)*
- **Навыки:** треугольники (подобие, теорема Пифагора, площадь), окружность (углы, касательные, хорды), четырёхугольники, площади фигур на клетчатой бумаге, декартовы координаты и векторы.
- **Пререквизит:** числа и вычисления, алгебраические выражения (для вычисления площадей/периметров через уравнения).
- **Тип задания:** часть 1 (базовые вычисления по чертежу) и часть 2 (доказательства, сложные построения) — по всем найденным источникам геометрия усилена в версии 2026 года.
- **Типовые ошибки:** неверное применение признаков подобия; путаница между теоремой синусов/косинусов и Пифагора; ошибка в переводе единиц площади.
- **Объяснение:** требует визуального компонента (чертёж) — сегодняшний тренажёр текстовый, без рендера геометрических фигур, это отдельное техническое требование, не только контентное.
- **Практика:** отсутствует полностью в текущем банке — это самый крупный содержательный разрыв графа знаний относительно кодификатора, при этом реализация (рендер чертежей, проверка ответов на многошаговые доказательства) — нетривиальная UI/UX и продуктовая задача, не только наполнение банка.

### 2.7 Реальная математика (практические задачи)
- **Навыки:** чтение таблиц/диаграмм, задачи на движение/работу/смеси, оценка и прикидка, работа с единицами измерения, бытовые расчёты (тарифы, вклады, скидки).
- **Пререквизит:** проценты, уравнения.
- **Тип задания:** часть 1, весь первый блок кодификатора («задания из реальной жизни»); по найденным источникам это направление усилено в 2026 году.
- **Типовые ошибки:** неверная интерпретация условия (путают, что является искомым), ошибки в единицах измерения.
- **Практика:** пересекается с «Проценты» в текущем коде, но как отдельная широкая категория (не только проценты) в графе не выделена.

### 2.8 Вероятность и статистика *(в коде есть — 2 задания)*
- **Навыки:** классическое определение вероятности, вероятность суммы/произведения событий, основы статистики (среднее, мода, медиана).
- **Пререквизит:** числа и вычисления.
- **Тип задания:** часть 1.
- **Практика:** минимально покрыто (2 задания) — низкий охват подтем внутри темы.

## 3. Модель знаний — русский язык

### 3.1 Изложение (сжатое) *(в коде НЕТ)*
- **Навыки:** приёмы сжатия текста (исключение, обобщение, упрощение), выделение микротем, сохранение авторского замысла при сокращении.
- **Пререквизит:** понимание прочитанного/прослушанного текста на уровне абзаца.
- **Тип задания:** часть экзамена №1, критерии ИК1–ИК3 ФИПИ.
- **Типовые ошибки:** искажение микротемы, механическое сокращение без понимания смысла, превышение/недобор объёма.
- **Объяснение:** требует оценки связного текста по критериям — не сравнение строки, а содержательная проверка; сегодня недостижимо без реального ИИ-сервиса (см. `docs/architecture/ai-tutor.md`, если создан).
- **Практика:** отсутствует полностью — самый сложный по автоматизации узел графа среди всех предметов.

### 3.2 Тестовая часть *(в коде частично — 4 темы из значительно более широкого набора)*
- **Навыки:** орфография (правописание приставок, суффиксов, -Н-/-НН-, слитно/раздельно), пунктуация (знаки при однородных членах, вводных словах, сложном предложении, прямой речи), морфология (части речи и их формы), синтаксис (грамматическая основа, виды связи в словосочетании, виды сложных предложений), фонетика, лексика (синонимы/антонимы/значение слова в контексте), анализ текста (средства связи предложений, средства выразительности).
- **Пререквизит:** для пунктуации — знание границ грамматической основы (синтаксис); для орфографии — знание морфемного состава слова (морфология).
- **Тип задания:** часть 2 нумерации ФИПИ (тестовая часть — не путать с «частью 2» математики), задания с кратким ответом (число/слово).
- **Типовые ошибки:** для пунктуации — не видят границу простых предложений в составе сложного; для орфографии — путают похожие по звучанию, но разные по написанию морфемы.
- **Практика:** в коде — Морфология, Орфография, Пунктуация, Фонетика (4 темы), нет синтаксиса, лексики, анализа текста и средств выразительности — значимая часть тестового блока не покрыта.

### 3.3 Сочинение (13.1 / 13.2 / 13.3) *(в коде НЕТ)*
- **Навыки:** формулировка тезиса, подбор аргументов (в т.ч. из прочитанного текста для 13.2), логичное построение вывода, соблюдение объёма и структуры (критерии СК1–СК4 ФИПИ).
- **Пререквизит:** понимание текста (как для изложения), умение письменно аргументировать.
- **Тип задания:** задание с развёрнутым ответом, свободная форма.
- **Объяснение и практика:** так же, как изложение — требует содержательной оценки текста по критериям, недостижимо без реального ИИ-сервиса; это прямое пересечение с Кандидатом 4 из `docs/product/04-killer-feature.md` («Автопроверка развёрнутого ответа»), отложенным до этапа Launch/V1.

## 4. Реализация в данных — куда это ложится

Граф из разделов 2–3 — вход для двух артефактов, которые пишутся отдельно в рамках этой же фазы аудита:
- `docs/architecture/adaptive-learning-engine.md` (если создан) — использует узлы Тема/Навык/Пререквизит как структуру Skill Graph для карты навыков (killer feature, `04-killer-feature.md`).
- `docs/architecture/03-database-design-v2.md` (если создан) — должен предусмотреть таблицы `topics`, `skills`, `skill_prerequisites` (граф, не плоский список) и связь `trainer_tasks.skill_id` вместо сегодняшнего плоского `topic` (текстовое поле без иерархии и пререквизитов, см. `axiom-backend/app/models/trainer.py`).

## 5. Приоритизация наполнения графа для MVP+

Не весь граф нужно наполнять сразу. Приоритет наполнения (детальные задания в банке) должен следовать выбранной killer feature (карта навыков) и текущему покрытию:

1. **P0 — формализовать граф для уже покрытых тем** (2.2, 2.4, 2.5, 2.8, 3.2) — добавить пререквизиты и поднавыки в модель данных без нового контента: это разблокирует карту навыков (killer feature) на существующих 45 заданиях без затрат на новый контент.
2. **P1 — расширить тестовую часть по русскому** (синтаксис, лексика, анализ текста) — тот же формат заданий (краткий ответ), что уже умеет тренажёр, просто больше контента.
3. **P1 — добавить геометрию как текстовые/числовые задачи части 1** (без чертежей — задачи, которые можно решить по описанию: «периметр прямоугольника со сторонами...») как временный компромисс, полноценный визуальный модуль — отдельная UI-задача.
4. **P2 — реальная математика как отдельная тема**, не растворённая в «Процентах».
5. **P3 (зависит от рабочего ИИ-сервиса) — изложение и сочинение** — не наполнять банк заданий до тех пор, пока нет механизма содержательной проверки текста; наполнение без проверки создаёт тот же риск «фиктивной функциональности», что уже отмечен как главная проблема продукта в `01-product-audit.md`.
6. **P3 — часть 2 математики (развёрнутое решение)** — та же причина: нет механизма проверки многошагового решения, наполнение банка без него бесполезно для ученика.

Детальное распределение по срокам — `docs/roadmap/product-roadmap-v2.md`; приоритизация фич продукта, а не контента — `docs/product/05-feature-prioritization.md`.
