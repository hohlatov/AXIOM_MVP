# 03 — Живой MVP vs код (Фаза 3)

> Метод: прямые HTTP-запросы (`curl`, а также `WebFetch` для рендер-описания) к `https://axiom-mvp.relaxdev.ru` (фронтенд) и `https://axiombackend.relaxdev.ru` (бэкенд), **без создания тестовых аккаунтов/данных** (правило аудита — не трогать прод-данные). Дата: 2026-09-11.

## Общий вывод

**Живой MVP на 100% соответствует коду в этом репозитории.** Значимых расхождений код↔прод не найдено — деплой (судя по совпадению API-схемы, коммит около `47ef249`) идёт из этого же репозитория без скрытых прод-патчей. Единственное существенное расхождение — между **заявленным продуктом** (питч-дек: RAG-ассистент на YandexGPT, CAT/IRT-диагностика, авто-проверка развёрнутых ответов) и **фактическим продуктом на проде**, что уже полностью объясняется несоответствием код↔документация (см. `04-documentation-gap-analysis.md`), а не проблемой деплоя.

## Конкретные проверки

### Фронтенд (`axiom-mvp.relaxdev.ru`)

| Проверка | Результат |
|---|---|
| `GET /` | Отдаёт статический SSR-шелл с заголовком «AXIOM — персональный ИИ-репетитор» и текстом «Загрузка…», без форм/навигации/контента — совпадает с `app/page.tsx` (клиентский редирект на `/dashboard` или `/login` после проверки токена в `localStorage`). Публичного маркетингового контента на `/` нет ни в коде, ни на проде — **лендинга нет**. |
| `GET /login` | HTML побайтово соответствует `app/login/page.tsx`: форма email/пароль, «Забыли пароль?», «Войти через VK ID», ссылка на регистрацию. |
| `GET /register` | Форма и **точный юридический текст согласия** («Я родитель/законный представитель ученика и даю согласие на обработку его персональных данных в соответствии с 152-ФЗ, либо ученику уже исполнилось 14 лет и он действует с согласия родителя») — совпадает дословно с кодом. |
| JS-бандл (`/_next/static/chunks/app/login/page-*.js`) | Содержит зашитый `NEXT_PUBLIC_API_URL=https://axiombackend.relaxdev.ru` — билд-таргет корректный, фронтенд смотрит на прод-бэкенд, а не на localhost. |
| Security-заголовки | Нет `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Strict-Transport-Security`, `Referrer-Policy`. Есть `X-Robots-Tag: noindex, follow` (индексация сознательно закрыта на уровне прокси — разумно для пре-продакшн MVP) и `X-Powered-By: Next.js` (лишний фингерпринтинг стека). |

### Бэкенд (`axiombackend.relaxdev.ru`)

| Проверка | Результат |
|---|---|
| `GET /health` | `200 OK`, тело `{"status":"ok"}` — совпадает с `app/main.py`. |
| `GET /docs`, `GET /openapi.json` | `200 OK`, **публично доступны без авторизации** (Swagger UI с заголовком «AXIOM API - Swagger UI»). См. `docs/security/security-audit.md`. |
| Список эндпоинтов в `openapi.json` | **1:1 совпадает** с роутами в `app/api/v1/*.py` — 16 путей (auth ×7, assistant ×2, dashboard ×1, diagnostics ×4, trainer ×2) плюс `/health`. Ни одного лишнего/отсутствующего. |
| `POST /api/v1/auth/register` с невалидными данными | `422`, тело — точные Pydantic-сообщения об ошибках (email/длина пароля), поведение идентично коду `schemas/user.py`, без побочных записей в БД. |
| Защищённые эндпоинты без токена (`/auth/me`, `/trainer/next-task`) | `401` — авторизация реально применяется на проде. |
| CORS preflight (`Origin: https://axiom-mvp.relaxdev.ru`, `OPTIONS /api/v1/auth/login`) | `Access-Control-Allow-Origin: https://axiom-mvp.relaxdev.ru`, `Allow-Credentials: true`, `Allow-Methods: DELETE, GET, HEAD, OPTIONS, PATCH, POST, PUT` — совпадает с `CORSMiddleware(allow_origins=[settings.frontend_url])`. Корректная конфигурация одного known-origin, не `allow_origins=["*"]`. |
| Security-заголовки бэкенда | Те же пробелы, что у фронтенда (нет CSP/HSTS/etc.), плюс `Server: uvicorn` — раскрывает ASGI-сервер. |

## Что НЕ было проверено на живом MVP (честно как UNKNOWN)

- Полный клик-сценарий «регистрация → диагностика → тренажёр → дашборд → ассистент» с реальным авторизованным пользователем на проде — не выполнялся, чтобы не плодить тестовые данные в боевой БД без согласования с владельцем продукта. README утверждает, что этот сценарий вручную подтверждён владельцем в реальном браузере, а сброс пароля прогнан end-to-end по API — это **доверенный источник, не переподтверждённый независимо** в этой сессии.
- Реальная отправка email при восстановлении пароля на проде (настроен ли `SMTP_HOST`, или письма падают в лог контейнера) — UNKNOWN, значение переменной окружения на проде аудиту недоступно.
- Фактическое значение `AI_SERVICE_MOCK` на проде — по умолчанию в коде `true`; ничто в открытых артефактах не позволяет однозначно установить прод-значение без авторизованного запроса. Отдельного задеплоенного домена/контейнера AI-сервиса Валентины в известной инфраструктуре не обнаружено, поэтому mock-режим на проде — наиболее вероятное состояние, но это **предположение, не факт**. Стоит явно подтвердить у владельца перед любой внешней демонстрацией — риск показать инвестору/жюри заглушку как «живой ИИ».
- Поведение rate limiting «за реальным реверс-прокси» — сам код содержит TODO о том, что `request.client.host` за прокси RelaxDev будет адресом прокси, а не клиента (`app/core/rate_limit.py`). Возможный риск — rate limit на проде либо ограничивает всех пользователей как один IP, либо (в зависимости от того, как прокси прокидывает адрес) недостаточно эффективен против точечного перебора одного реального адреса. Проверить напрямую без десятков реальных запросов к проду (запрещено правилами аудита) нельзя — фиксируется как **приоритетный пункт для ручной проверки владельцем**, не как подтверждённый факт.
- TLS-конфигурация (версии протокола, шифры) — не проверялась, не входила в объём аудита.

## Рекомендации

1. Перед любой демонстрацией живого MVP явно проверить значение `AI_SERVICE_MOCK` на проде.
2. Закрыть `/docs`/`openapi.json` от анонимного доступа на проде (Basic Auth на прокси или `FastAPI(docs_url=None)` + защищённый путь) — недорого, риск низкий, но легко устраняется.
3. Спланировать минимальный публичный лендинг на `/` — сейчас первый контакт любого пользователя с продуктом это форма логина, что плохо для конверсии и виральности в GTM-каналах.
4. Владельцу — вручную подтвердить и задокументировать реальную конфигурацию прод-окружения (`AI_SERVICE_MOCK`, `SMTP_HOST`, поведение rate limit за прокси), поскольку внешний аудит физически не может проверить эти значения без доступа к прод-`.env`.
